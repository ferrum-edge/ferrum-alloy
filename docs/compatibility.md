# Compatibility

This page records what has actually been tested. Anything not listed is untested. Edge's broader protocol support, such as HTTP/3, gRPC, and mesh modes, does **not** imply Alloy support.

The same pairing in machine-readable form is in [compatibility.json](compatibility.json).

## Supported Edge releases

Alloy supports **the latest Ferrum Edge release and the release before it**. CI reads `edge_support.tested` from [compatibility.json](compatibility.json) and runs the `Ferrum Edge end-to-end` and `Generated Edge configuration validates` jobs once for each release below, named `(baseline)` for the first row and `(previous)` for the second. The first row is the contract baseline above; the demo stack uses it unless `EDGE_IMAGE` is set.

- **Differences inside the window.** v0.9.8 added the `request_timeout` token to `X-Gateway-Error` and strips backend-supplied copies of `X-Gateway-Error` and `X-Gateway-Upstream-Status`. v0.9.7 does neither. Alloy's diagnosis accepts both token sets. Because a response header names no Edge version, `backend_timeout` keeps its v0.9.7 meaning (a backend or route deadline elapsed), and a header alone never exceeds `likely`.
- **Unsupported releases.** Older releases and unreleased Edge `main` are not tested. Alloy does not refuse to run behind them, but nothing in the inventory is claimed for them. Diagnosis treats their tokens and attributes by the same rules: an unknown `X-Gateway-Error` token yields `unknown`, never a guessed meaning.
- **New releases.** `.github/workflows/edge-bump.yml` checks for a new Edge release every day. When it finds one, it resolves the tag's multi-arch index digest, verifies with Cosign that Edge's release workflow signed that digest for the tag and its source commit (the run fails otherwise), and opens a draft pull request that makes the new release the baseline, keeps the previous baseline as the second supported release, and drops the oldest. The same CI jobs then prove or disprove compatibility. Its pull request still needs the re-audit below before it merges.

## Topology tested end to end

```text
client ──HTTP/1.1──▶ Ferrum Edge ──HTTPS + mTLS (SPIFFE SVID-style client cert)──▶ Alloy ──▶ simulated dependency
                      │  OTLP/HTTP JSON                                              │  OTLP/HTTP protobuf
                      └────────────────────────▶ OpenTelemetry Collector ◀───────────┘
```

| Leg | Protocol observed |
|---|---|
| Client → Edge | HTTP/1.1, plaintext, port 8000 |
| Edge → Alloy | HTTPS. Alloy spans recorded `network.protocol.version = 2`, so Edge negotiated HTTP/2 through ALPN. |
| Direct client → Alloy (bypass check) | HTTPS, HTTP/1.1, no client certificate → `403 gateway-required` |
| Edge → Collector | OTLP/HTTP **JSON** (`POST /v1/traces`) |
| Alloy → Collector | OTLP/HTTP **protobuf** (`POST /v1/traces`) |
| Trust mode | `gateway_required`; `trust.identities = ["spiffe://ferrum.demo/ns/edge/sa/gateway"]`; `server.tls.client_auth = optional` |
| Edge connection pool | `FERRUM_POOL_WARMUP_ENABLED=false`, `FERRUM_POOL_HTTP2_CONNECTIONS_PER_HOST=1`, so connection identity is deterministic. Edge's defaults are not exercised. |

What that job verifies is listed in [ADR 0007](adr/0007-real-gateway-integration-testing.md). The first local run passed the original 19 checks. The attempt and connection cases below were added afterwards and are verified by CI, bringing the job to 46 named checks.

### Attempt and connection cases

Both supported releases run every case; none is gated by release. The extra proxies come from `gen-e2e-edge-config`, which appends them to the unchanged `ferrum-alloy edge export` output, and every fault is produced inside the compose network.

| Case | How it is produced | What is checked |
|---|---|---|
| Retry | Alloy's `/flaky/{key}` fails the first attempt with `503`; proxy `e2e-retry` retries `503` once (`retry` block, default 100 ms backoff). | Two Alloy SERVER spans with the same Edge parent (`503`, then `200`), Edge `backend_ttfb` of at least both attempts' time to headers plus the backoff, and a diagnosis that reports `alloy.gateway.multiple_service_attempts`, compares no timings, assigns nothing to an attempt, and confirms nothing. |
| Cold and reused connection | Proxy `e2e-reuse` uses the `alloy-reuse` alias; Alloy counts every request per connection on every route, and `/conn` reports how many earlier requests its connection carried. | The first request's connection carried no earlier request, a later one reused one, and neither request's spans or diagnosis carry a connection-setup value. |
| Concurrent HTTP/2 streams | Six concurrent requests through `e2e-reuse`; Alloy's `/gather/6` waits until all six are in the handler. | Six overlapping Alloy SERVER spans over HTTP/2, each under its own Edge span, on fewer than six connections, with no setup charged to any stream. |
| Client cancellation mid-body | The driver closes its connection after the first frame of a 4 s event stream. | Edge records the client disconnect; one Alloy SERVER span with outcome `cancelled`, ended mid-stream, and one `alloy.response.body_incomplete` finding. |
| Refused connection | Proxy `e2e-refused` targets a port on the Alloy container with no listener. | `X-Gateway-Error: connection_failure`, an Edge span with `gateway.error.class` and no Alloy span, and a `likely` diagnosis that does not claim the service is down. |

Not covered: an upstream reset after a connection is established, and per-attempt timing, which Edge v0.9.8 and v0.9.7 do not record.

## Semantic conventions

- HTTP span and metric attribute names follow the **stable** OpenTelemetry HTTP conventions: `http.request.method`, `http.route`, `http.response.status_code`, `url.scheme`, `network.protocol.version`, `error.type`, `server.address`, `server.port`, and the optional `url.path`, `client.address`, `user_agent.original`.
- Database operations use `db.system.name`, `db.operation.name`, and `db.query.summary` from the database conventions, which are not all stable.
- The Prometheus histogram `http_server_request_duration_seconds` (OpenTelemetry `http.server.request.duration`) uses Alloy's documented boundaries: middleware entry to body finalization.
- Alloy-specific data uses the `alloy.*` prefix.
- **No `schema_url` is emitted.** Ferrum Edge v0.9.8 emits none either, and its `http.route` holds the proxy name, not a template.

## Pairing rules

- Moving to a new Edge release requires:
  1. updating the image digest in `compatibility.json` (`edge` and `edge_support.tested`, which is CI's Edge matrix), `examples/edge-observability/Dockerfile` (`EDGE_IMAGE` default), and this page;
  2. updating `ferrum_alloy_edge::contract::{EDGE_RELEASE, EDGE_SOURCE_COMMIT}`, the headers of `contracts/fixtures/manifests/*.edge.yaml` (`UPDATE_SNAPSHOTS=1`), and the release the CLI test expects;
  3. re-auditing the contract inventory (checklist below);
  4. passing the `Ferrum Edge end-to-end` and `Generated Edge configuration validates` jobs for every supported release.
- `crates/ferrum-alloy-edge/tests/pairing.rs` fails when steps 1 and 2 disagree, when the window is not two releases led by the baseline, when `ci.yml` stops reading its Edge matrix from `compatibility.json` or pins an Edge image itself, or when `contract::GATEWAY_ERROR_TOKENS` and the diagnostics catalog differ.
- Unreleased Edge main is never pinned.

### Re-audit checklist

Run it against the new release's tag in the Edge repository, and record the result in the revision table of [edge-contract-inventory.md](edge-contract-inventory.md).

1. `git diff <old-tag> <new-tag> --stat -- src/plugins/otel_tracing.rs src/plugins/correlation_id.rs src/config/types.rs src/proxy/headers.rs src/retry.rs`. An unchanged file keeps its entries; re-read every entry backed by a changed file.
2. `src/retry.rs`: the `X-Gateway-Error` vocabulary (`HTTP_OBSERVABILITY_ERROR_CLASSES`). Mirror additions in `contract::GATEWAY_ERROR_TOKENS`, `catalog::EDGE_GATEWAY_ERROR_TOKENS`, and the `does_not_prove` list of rule `alloy.r007`, and state what each new token does not prove. Never narrow an existing token's meaning: a header names no Edge version. Bump `contracts/ferrum-contracts/PIN` to the matching `contracts-edge-*` tag and re-verify the vendored vocabularies (see [contracts/README.md](../contracts/README.md#ferrum-contracts-pin)); their release-specific meanings are recorded in the pairing test, never rendered.
3. `src/proxy/headers.rs`: which gateway-owned response headers are stripped from backend responses, and which request headers Edge overwrites.
4. `src/plugins/otel_tracing.rs`: span kinds, `gateway.*` attribute names and meanings, and `traceparent` parsing. New timing fields go through `measurement-semantics.md` and `catalog.rs` first.
5. `src/plugins/correlation_id.rs`: the accepted request-id grammar (mirrored in `ferrum-alloy-telemetry`).
6. `src/config/types.rs` and the `otel_tracing` `ALLOWED_CONFIG_KEYS`: every field `ferrum-alloy edge export` writes (the `edge-config` job validates the fixture).
7. `docs/plugin_execution_order.md` and the `rejection_phase` values: `catalog::EDGE_PRE_UPSTREAM_PHASES`.
8. `src/plugins/mod.rs`: the reserved `x-consumer-*` names stripped from clients.
9. Entries marked UNAVAILABLE: check whether the release now produces them. A new contract stays PROPOSED here until it is verified in a release.

# Ferrum Alloy v0.1.0

Released 2026-11-21. This is the first release of Ferrum Alloy, a batteries-included toolkit for Rust API services built on Axum, with first-class support for running behind [Ferrum Edge](https://github.com/ferrum-edge/ferrum-edge).

## Distribution

Alloy is distributed from Git only ([distribution decision](../release.md#distribution-decision), #24). The release is the Git tag `v0.1.0`; no crate is published to crates.io or any other registry, and every crate keeps `publish = false`. The release ships no build artifacts.

Depend on the release by tag:

```toml
[dependencies]
ferrum-alloy = { git = "https://github.com/ferrum-edge/ferrum-alloy", tag = "v0.1.0" }
```

Install the CLI from the tag and generate a starter pinned to this release:

```bash
cargo install --locked --git https://github.com/ferrum-edge/ferrum-alloy --tag v0.1.0 ferrum-alloy-cli
ferrum-alloy new <name> --alloy-tag v0.1.0
```

`--locked` installs the dependency versions in the tag's `Cargo.lock`, which CI tested. By default, `ferrum-alloy new` writes a git dependency that follows `main`; `--alloy-tag`, `--alloy-branch`, `--alloy-rev`, and `--alloy-path` change it ([getting started](../getting-started.md)).

## Requirements

- **MSRV:** Rust 1.94 (`rust-version`, set by sqlx 0.9). This is the first release, so there is no MSRV change. CI builds with Rust 1.98.1 (`rust-toolchain.toml`) and checks the MSRV in the `MSRV (1.94)` job.
- **Platforms:** CI tests Linux x86_64, macOS, and Windows; the Docker-based jobs run on Linux x86_64 ([compatibility](../compatibility.md#platforms)).

## What is in v0.1.0

The [changelog](../../CHANGELOG.md#010---2026-11-21) lists every change. In summary:

- **Service runtime.** `AlloyApp` on Axum and Hyper: layered configuration (`alloy.toml` and `FERRUM_ALLOY_*`), Problem Details errors, health and readiness, request and connection limits (including body-read stall and HTTP/2 flow-control protections), graceful shutdown with a drain budget, and a separate management listener whose detailed health, metrics, and management OpenAPI/UI require a management token (status-only probes do not).
- **Telemetry.** Request telemetry with stable OpenTelemetry HTTP attribute names, Prometheus metrics, OTLP trace export (bounded, chunked, and never failing requests), and request-ID handling that trusts incoming IDs only from trusted peers by default.
- **Integrations.** TLS and mTLS with rustls, JWT verification against a JWKS, PostgreSQL through sqlx with migrations, an outbound HTTP client with explicit timeouts and redirects off by default, and OpenAPI 3.1 documents with an optional Swagger UI.
- **Ferrum Edge** (feature `edge`, not in default features). Edge modes `standalone`, `gateway_preferred`, and `gateway_required`. `gateway_required` serves application requests only from a verified gateway identity (mTLS); with `health.app_endpoints = true`, Alloy's status-only liveness and readiness routes are exempt so probes work. On requests it processes, the Edge policy removes gateway-asserted request headers unless the request comes from a verified gateway identity with `edge.accept_consumer_identity = true`. A configured network boundary (`trust.networks`) enables trusted-peer behavior (trace context, request IDs, `Server-Timing`) and is reported to handlers as `GatewayVerification::NetworkTrusted`; it never satisfies `gateway_required` or identity handoff. Also: the service manifest, `ferrum-alloy edge export` for Edge file-mode YAML or a GitForgeOps tree, and `x-ferrum-mcp` agent tools.
- **Diagnostics.** Retained diagnostic evidence and `ferrum-alloy diagnose`, which explains a request from service evidence, OTLP files, and authenticated Edge diagnostic-reference lookups, stating what the evidence does and does not prove.
- **CLI.** `ferrum-alloy new` starters (`--with openapi,otel,edge,tls,postgres,jwt,http-client`), `check`, `openapi export`, `edge export`, `diagnose`, and `version`.
- **Security.** The changelog records the security fixes made before this release, including the gateway-asserted header and trace-context hardening and dependency updates for RustSec advisories. `deny.toml` carries two time-boxed advisory exceptions, both reached only through jsonwebtoken's `rust_crypto` backend (feature `jwt`, which verifies signatures with public keys only) and both expiring on 2026-12-26: RUSTSEC-2023-0071 (`rsa` 0.9.10) and RUSTSEC-2026-0387 (`crypto-bigint` 0.5.5, owner-accepted on 2026-11-14, #294). See [the security model](../security.md#jwt--jwks-feature-jwt).

Entries marked **Breaking** or **Behavior change** in the changelog describe changes relative to earlier `main` commits. They matter if you depended on Alloy by revision before this release.

## Known limits

- The OpenTelemetry Rust tracing API and SDK that Alloy uses are documented upstream as beta.
- Service-side HTTP/3, gRPC tooling, and WebSocket message tracing are not supported.
- Before 1.0, a breaking change bumps the minor version.

## Release checklist evidence

Every item of the [release checklist](../release.md#release-checklist) is recorded here or on the GitHub release for `v0.1.0`; the items marked *registry only* do not apply to a Git release.

- **Owner approval:** the owner approved this first release on 2026-11-21.
- **Version:** all five crates share `workspace.package.version = "0.1.0"`.
- **Security review:** the release pull request was reviewed read-only at its exact head commit by two independent AI reviewers (GPT-6.2 Sol at xhigh effort and Gemini 4 Neon at high effort) against [the security model](../security.md), as the release's security review. Findings and their dispositions are recorded in the release pull request, [#331](https://github.com/ferrum-edge/ferrum-alloy/pull/331).
- **Benchmark baseline:** not a release gate. The owner closed #15 as not planned on 2026-11-04, so the committed budgets and the manually dispatched regression gate are diagnostic only ([benchmarks](../benchmarks.md#regression-gate)); no regression-gate run is claimed for this release.
- **SBOM and provenance:** a CycloneDX SBOM generated from `Cargo.lock` at the tagged commit is attached to the GitHub release. The release ships no build artifacts, so there is no provenance subject and no attestation is claimed.
- **Merge, tag, and CI evidence:** the release commit is the GitHub merge commit of the release pull request. The tag, that commit, and its green `push` CI run are recorded on the GitHub release.

# ADR 0007: Prove Edge integration with a pinned real gateway

**Status:** Accepted (2026-09-26). The single pinned release below is superseded by the two-release matrix in `docs/compatibility.json` (`edge_support.tested`).

## Context

A header-echo mock can pass while the real gateway behaves differently: which span becomes the parent, retry behavior, `-1` sentinels, OTLP encoding, or backend mTLS details.

## Decision

- CI runs a published Ferrum Edge image pinned by digest (v0.9.7, the same digest Ferrum Foundry pins), an OpenTelemetry Collector pinned by digest (contrib 0.161.0), and the Alloy example, on one compose network.
- Edge configuration is generated by `ferrum-alloy edge export` and checked with `ferrum-edge validate` before use. Demo certificates are generated at build time. No host bind mounts are used, so the stack runs the same under colima and in CI.
- `edge-e2e` asserts facts from the collector's exported spans:
  - the Alloy SERVER span is parented by the Edge SERVER span and by the parent Edge echoed to the client;
  - Alloy accepted that context only from the verified SPIFFE identity;
  - Edge's request id was reused;
  - the operation span nests under the service span;
  - a streamed span covers its body;
  - direct access is rejected;
  - offline diagnosis stays at `likely`.
- The collected spans, summary, diagnosis, and service logs are uploaded as CI artifacts.

## Consequences

- Moving to a new Edge release means updating the digest, re-running the contract inventory, and re-running this job.
